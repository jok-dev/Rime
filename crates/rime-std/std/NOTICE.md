# Selene standard-library files

`lua51.yml`, `luau.yml` and `roblox.yml` in this folder come from Selene,
https://github.com/Kampfkarren/selene, which is licensed under MPL-2.0.

All three are built into the `rime` executable. So is the list of
functions whose result must be used, in
`crates/rime-check/src/rules/must_use.rs`, which was made with Selene from
its standard-library files.

This folder, in the rime repository, is the source of the three files as
rime is built from them. The text of MPL-2.0 is the file `LICENSE` at the
root of the repository; a release publishes it beside the executables.

Where each file came from:

- `lua51.yml`: copied from
  https://github.com/Kampfkarren/selene (`selene-lib/default_std/lua51.yml`),
  snapshot of commit `3ebc0b34c29226d59f2e69503803525c6ea5e25b` (2023-09-29,
  last commit to touch this path as of the fetch below).
- `luau.yml`: copied from
  https://github.com/Kampfkarren/selene (`selene-lib/default_std/luau.yml`),
  snapshot of commit `33a77154d008506b3443be363d4d8c265e01b104` (2026-01-23,
  last commit to touch this path as of the fetch below).
- Both files fetched 2026-08-22 from the `main` branch, which was at
  `9d531b8d3755e139b26c534914e252239014bb3d` at fetch time.
- `roblox.yml`: generated by `selene generate-roblox-std` on 2026-08-22;
  merges selene's `roblox_base.yml` with the Roblox API dump (the
  generator embeds the full resolved global set, including lua51/luau
  globals, directly in this file even though it also carries
  `base: luau`). The generator's `last_selene_version` line is left out:
  Rime does not read it.

These are data files; keep this note next to them, under this name:
`scripts/third-party-notices.py` copies it into the notices file of every
release and fails without it. Rime reads only the global NAMES today; the
signature data is not used yet.
